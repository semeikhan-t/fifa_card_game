1. О проекте
FIFA Card Game 2026 - простая десктопная игра на JavaFX. Пользователь выбирает страну, собирает состав из игроков этой сборной и запускает быстрый матч (≤40 секунд) против другой сборной. Результат определяется алгоритмически на основе рейтингов.

4. Логика матча
Матч симулируется быстро - анимация длится не дольше 40 секунд. Алгоритм простой:

Считается средний overall каждой команды из выбранных 11 игроков.
Количество голов каждой команды определяется случайно с учётом разницы рейтингов:
Чем выше ovr - тем выше шанс забить (но не гарантия).
Добавляется случайный фактор ±20%, чтобы слабая команда могла победить.
Базовый диапазон голов: 0-4 за матч для каждой команды.
Для каждого гола случайно выбирается игрок из атакующих позиций (FWD / MID).
Голам назначается случайная минута (1-90).
События показываются на экране по одному с короткой паузой (итого ≤40 сек).

7. Принципы ООП в проекте
Все четыре основных принципа ООП должны быть явно применены в коде.

Инкапсуляция
Все поля классов модели (Player, Team, MatchResult) объявляются private. Доступ - только через геттеры/сеттеры. Логика матча скрыта внутри MatchService и не доступна напрямую из контроллеров.
Наследование
Базовый абстрактный класс Entity содержит общие поля (id). Player, Team, MatchResult наследуют от него. Для слоя БД - базовый AbstractDAO&lt;T> с методами findById, findAll, save; конкретные DAO его расширяют.

Полиморфизм
Интерфейс DAO&lt;T> объявляет findById, findAll, save. PlayerDAO и TeamDAO реализуют его по-своему. Контроллеры работают с типом DAO&lt;T>, не зная о деталях реализации. Также используется перегрузка метода simulate() в MatchService.

Абстракция
Контроллер видит только высокоуровневый метод MatchService.simulate(home, away) - он возвращает готовый MatchResult. Детали расчёта голов, выбора голеадоров и генерации событий скрыты внутри сервиса. DAO аналогично скрывает весь SQL от бизнес-логики.
